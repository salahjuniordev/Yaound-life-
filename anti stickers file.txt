

Objective

Maintain a professional, immersive, realistic 3D life-simulation experience. The entire game interface, world, menus, notifications, NPC interactions, HUD, and system messages must use clean text, realistic visual assets, and a consistent design system.

Emojis and stickers are prohibited everywhere in the game except inside messaging conversations where players communicate with other characters or players.

This is a mandatory design requirement, not an optional styling preference.

1. Prohibited Uses

Never use emojis, Unicode pictographs, decorative emoticons, or stickers in the following areas:

- Main menu, loading screens, onboarding, and character creation.
- Game HUD, status bars, health, hunger, energy, mood, and needs indicators.
- Navigation menus, buttons, tabs, toolbars, and dropdowns.
- Inventory, clothing, equipment, and customization interfaces.
- Maps, location markers, business markers, and navigation directions.
- Quest logs, missions, achievements, objectives, and progress indicators.
- Notifications, alerts, toast messages, system announcements, and error messages.
- NPC dialogue boxes, subtitles, dialogue choices, and interaction prompts.
- Job boards, business dashboards, banking, mobile money, and marketplaces.
- Housing interfaces, property management, and furniture customization.
- Calendar, events, festivals, activities, and public announcements.
- Settings, account screens, authentication, and accessibility interfaces.
- Tutorials, help screens, tooltips, empty states, and confirmation dialogs.
- Game-generated social feed posts, headlines, and promotional banners.
- Developer-created placeholder content, sample data, and test fixtures.

Do not replace emojis with ASCII emoticons such as ":)", ":D", ";)", or decorative text symbols.

2. The Only Exception: Messaging Conversations

Emojis and stickers may be used inside actual communication interfaces, including:

- Private player-to-player messages.
- NPC text-message conversations.
- Group chats.
- Messaging apps inside the character's phone.
- Player-authored chat messages in supported multiplayer features.
- Stickers deliberately sent by a player as part of a conversation.

These elements must be treated as user-generated conversational content, not as decorative UI elements.

A player sending a message such as "See you tonight" may include an emoji or sticker. The game must preserve that content when displaying the message.

Do not automatically add emojis or stickers to messages generated by the game, NPCs, or system notifications. NPCs may use them only when explicitly justified by their conversational personality and the messaging system's design.

3. Replace Emojis With Proper UI Assets

Wherever an emoji is currently being used as an interface icon, replace it with an appropriate alternative:

- Use a consistent icon library, such as Lucide, for standard interface controls.
- Use custom SVG icons for game-specific concepts.
- Use realistic 3D models and recognizable objects inside the 3D world.
- Use proper illustrations, textures, and thumbnails where appropriate.
- Use text labels alongside icons when the meaning might not be immediately clear.
- Use subtle visual indicators, badges, typography, and color to communicate status.
- Use actual character portraits or profile images instead of decorative emoji faces.

Examples:

- Replace a money-bag emoji with a clean currency icon and an FCFA balance.
- Replace a house emoji with a proper house icon or property thumbnail.
- Replace a car emoji with a vehicle icon or a 3D vehicle model.
- Replace a food emoji with a food icon or a realistic food image.
- Replace a heart emoji in a relationship meter with a professionally designed relationship indicator.
- Replace a briefcase emoji in job listings with a consistent employment icon.
- Replace weather emojis with a coherent weather icon set or an appropriate environmental visualization.
- Replace achievement emojis with designed achievement emblems.
- Replace emoji-based quest markers with consistent icons, typography, and clear objective labels.

Do not simply replace every emoji with a different decorative symbol. Every icon must have a clear purpose and belong to the game's visual design system.

4. Visual Design Standards

The game must feel like a polished, modern 3D life simulator rather than a casual messaging app or an emoji-based mobile game.

Follow these principles:

- Maintain a consistent icon style, size, stroke weight, and alignment.
- Use professional typography and a clear visual hierarchy.
- Prefer restrained, purposeful visual effects over excessive decoration.
- Use realistic world assets that fit the setting of Yaoundé, Cameroon.
- Keep the HUD readable and unobtrusive during gameplay.
- Use proper interface states for selected, active, disabled, successful, and failed actions.
- Do not use emojis as substitutes for real character expressions, animations, objects, or environmental details.
- Keep the interface suitable for desktop and mobile browsers.
- Preserve accessibility, contrast, and clear text labels.

5. Codebase Audit and Implementation

Before making changes:

1. Inspect the existing codebase and identify every use of emojis, stickers, emoticons, and decorative Unicode symbols.
2. Locate the components, data files, configuration, content definitions, and utilities responsible for rendering them.
3. Separate system-generated UI content from user-generated messaging content.
4. Identify existing icon libraries and reusable design-system components.

Then implement the rule throughout the project.

- Replace prohibited decorative emojis with proper icons, assets, or text.
- Create reusable icon components where necessary.
- Preserve legitimate emojis and stickers inside messaging conversations.
- Ensure message rendering supports legitimate conversational content without allowing it to leak into unrelated UI.
- Preserve existing game functionality, gameplay logic, data structures, and responsive layouts.
- Avoid unnecessary dependencies and do not rebuild unrelated systems.
- Do not introduce new emojis or stickers during the replacement process.

6. Validation and Acceptance Criteria

The implementation is complete only when all of the following conditions are met:

1. No decorative emojis or stickers appear anywhere in the game outside messaging conversations.
2. All navigation, HUD, menus, buttons, notifications, quests, events, and system-generated interfaces use approved icons or text.
3. Player-authored messages can still contain emojis and stickers.
4. Ordinary message text, punctuation, multilingual content, and supported conversational formatting continue to work.
5. NPC dialogue outside messaging interfaces contains no emojis or decorative emoticons.
6. No existing gameplay functionality is broken by the changes.
7. A codebase-wide search has been performed for emoji characters, sticker assets, emoticons, and suspicious Unicode pictographs.
8. Screenshots or visual tests have been reviewed for the main menu, HUD, phone interface, quests, events, inventory, business dashboard, and messaging screen.
9. Automated tests verify the intended restrictions without incorrectly blocking legitimate messaging content.
10. The final report identifies the main files changed, replacements made, tests performed, and any remaining exceptions.

7. Important Implementation Notes

Do not blindly delete every Unicode character outside the Basic Multilingual Plane. Some legitimate text, language characters, and accessibility-related symbols may be encoded there.

Do not block emoji characters globally at the database or authentication layer. This rule governs presentation and game-generated content, not the player's ability to express themselves in permitted messaging interfaces.

Use a centralized icon system and shared components wherever practical so future features follow the same rules.

Do not claim completion until the relevant code changes and validation have actually been performed.
